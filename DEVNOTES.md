# GatherPath Forever — developer notes

Gathering routes for **World of Warcraft: Forever** (interface 16001): the shortest loop through the herb and ore nodes GatherMate2 has recorded, drawn on the world map and the minimap.

- Author: `severd8`. License: MIT.
- CurseForge project ID: `1747649` (in the `.toc` as `X-Curse-Project-ID`).
- Sister addons: TauntMaster Forever, ToppedOff Forever, Outfitter Forever, BattleText Forever. This project's setup mirrors BattleText's.
- README.md and CURSEFORGE.md recommend GatherMate2 Data (Wowhead Classic) (https://www.curseforge.com/wow/addons/gathermate2-data-wowhead-classic), whose nodes players import through GatherMate2's Import Data options. Nothing in the code depends on it (since 1.0.1).
- Written from scratch. It does the job of the old Routes addon but uses none of its code (Routes is All Rights Reserved; its TSP.lua is GPL). GatherMate2 (also All Rights Reserved) is only called through its functions and messages at run time, never copied.

## Files

- `GatherPathForever.toc` — `## Version: @project-version@` is filled in by the packager from the git tag. `## OptionalDeps: GatherMate2` so GatherMate2 loads first when it's there. `GatherPathForeverDB` holds the settings and the routes (shared by every character).
- `Theme.lua` — **the shared look, the same file in all five addons.** Change it in one repo, then copy it to the others. Its `BRANDS` table has a `GatherPathForever` row; the other four repos' copies don't have it yet (harmless: each only needs its own row), so copy this one over next time Theme.lua changes there.
- `Optimize.lua` — the route solver, plain Lua with no game calls (the tests load it on its own). Points are `{ x, y }` in yards. `O.Solve` starts from the nearest-neighbour tour, then repeats 2-opt (`TwoOpt`, uncrossing legs) and Or-opt (`OrOpt`, moving runs of 1–3 nodes) until neither shortens it. `O.Group(points, radius)` (since 1.3.0, replacing `O.Merge`) puts the nodes within `radius` of the first ungrouped one into a group; its spot is their middle, or that first node if the middle would leave one further than `radius` away (`count`, `reach` = yards to its furthest node). `O.BestInsert` is the cheapest place for one new node. `O.Shortcut(nodes, radius)` (the "Route passes within" setting): since 1.3.0 first groups the nodes with `O.Group(nodes, radius / 2)` (ungrouped if that leaves fewer than 2 spots), solves the loop through the spots, then sweeps each stop to `O.Place` (the spot within `radius - reach` of its group with the shortest prev -> spot -> next: on the straight line if it passes close enough, else a golden-section search on the half circle facing it), re-runs 2-opt/Or-opt on the moved stops, up to 4 rounds, then drops stops within 0.3 yards of the line between their neighbours. Every node stays within radius (+0.5) of the loop; never longer than the plain loop. Grouping (measured on ~540 nodes in patches of 1-8 within 30 yards, and 500 spread out, 1500 x 1000 yards, at 100 yards): 36% shorter on patches (10553 -> 6770 yards, 140 -> 38 stops, 3.9 s -> 0.1 s), 35% on spread nodes (13939 -> 8916); grouping at a quarter or three quarters of the radius did worse than half. It replaced the "Merge nodes closer than"/"Combine nodes within" slider (route field `merge`, `O.Merge` chained groups to their middle, so with Pass within on nodes could end up further away than promised). Every few thousand steps it calls `O.Pause()`, which `GP:RunJob` sets to a coroutine yield.
- `Core.lua` — settings (`GP.DEFAULTS`, `GP.RANGES`, `LoadSettings` drops broken routes and clamps numbers), GatherMate2 (`EachNode`, `ZoneNodes`, `GatherZones`, `CollectNodes`), routes (`NewRoute`, `EditRoute`, `RebuildRoute`, `DeleteRoute`, `RenameRoute`, `SetRouteShown`, `SetRouteColor`, `AddNode`, `RemoveNode`), the world map pin and data provider, the minimap lines, the minimap button, `/gpf`, events.
- `Pin.xml` — `GatherPathForeverPinTemplate`, the world map pin (mixin `GatherPathForeverPinMixin` in Core.lua). Templates for `AcquirePin` have to be XML.
- `Options.lua` — the window, built with `Theme.Window`: Routes (rows 74 apart: a color square, a name box, Edit, Rebuild, Delete on top; info on two lines (nodes, length, kinds; then passes within) and Show below, since 1.2.1), New route (zone dropdown, a switch per kind of node with its count, grouped by kind, name, "Route passes within" slider (`sight`; "Pass within" until 1.2.1), Make route), Display. New route starts blank every time it's shown (`ResetNew`, from the window's `onTab`/`onShow`): no zone, no picks, no name, the slider at `GP.DEFAULTS.sight` (since 1.2.0; before, the zone started on yours and the sliders remembered the last route in `db.merge`/`db.sight`, which are now not read; the 1.1.1 50-to-100 step in `LoadSettings`, flag `db.sight100`, is left in but no longer matters). Since 1.6.0 each kind's heading has Select all (`heads[i].all`, entries of that kind in `.entries`; reads Clear all when every one is on), and the name box starts with `Prefix(newZone)` ("Zone - ", following zone changes while the box holds only a prefix, `prefixZone`); a name that is only the prefix or blank becomes prefix .. `GP:RouteName` on Make/Save (done in Options.lua; `GP:NewRoute` itself still makes names without the zone). The grey hint sits after the prefix, measured with a hidden FontString. The Routes tab's New route button (`GP:NewRouteInWindow(routesZone)`, since 1.4.0) opens it blank but with `newZone` set to the Routes tab's zone; the sidebar tab and `/gpf new` still start with none. Edit on a row (`GP:EditRouteInWindow`) fills the same tab from the route; its title reads Edit route, Make route becomes Save changes (`GP:EditRoute`) and a Cancel shows. If that route is deleted meanwhile the tab goes blank. Display: the Lines card has a column per map (switch, width, opacity, "Each route's own color", a Line color square greyed out while that's on; since 1.5.0). `Swatch(parent, get, set, title, tip)` is the color square on route rows and there. `GP.ui` keeps the widgets the tests use. `GP:Confirm` is the themed "are you sure" window.

## Routes

- `LoadSettings` clears `merge` from routes and `db` (since 1.3.0); their saved `points` are kept, so old routes look the same until Rebuild/Edit.
- A route: `id`, `mapID`, `name`, `kinds` (`{ [GatherMate2 kind] = { [node name] = true } }`), `sight` (yards the loop passes within of each node, 0 = off; missing on 1.0 routes = 0), `nodes` (how many nodes it was made from; `GP:RouteNodes`, falls back to `NodeCount` = stops), `color` `{r,g,b}`, `shown`, `points` (flat `{ x1, y1, x2, y2, ... }`, map positions 0–1 rounded to 4 places, in loop order), `length` (yards). `working` is set while the solver runs (not drawn, not added to).
- Editing (`GP:EditRoute(route, opts)`, since 1.2.0): same checks as `NewRoute` (the name check skips the route itself), sets the new zone, kinds, name and sight, then `Build`s it in a job keeping `id`, `color` and `shown`. If no loop comes out (fewer than 2 stops) every changed field goes back. `opts.mapID` missing = its own zone.
- Names are unique per zone (since 1.0.2): `GP:RouteNamed(mapID, name, except)` compares trimmed, case-insensitively. `NewRoute` (typed or made-up name) and `RenameRoute` turn a taken name down with a chat line; `RenameRoute` returns false and the row's box goes back to the old name. Before this, a same-named route with the same nodes drew the identical loop under the first one, so it looked missing. Saved duplicates from 1.0.0/1.0.1 are left as they are.
- Yards: `GP:MapYards(mapID)` from `C_Map.GetMapWorldSize`, else the world positions of the map's corners (`C_Map.GetWorldPosFromMapPos`; the world's x runs north, y west). A map the game can't measure is taken as 1500 x 1000 for the solver.
- Work is spread over frames (`GP:RunJob`): one job at a time, ~10 ms a frame (`debugprofilestop`). 600 nodes is about 3 s of work outside the game.
- GatherMate2: `GetNodesForZone(mapID, kind, true)` (coord, nodeID), `DecodeLoc(coord)` (x, y), `GetNameForNode(kind, nodeID)`, `db_types`. Zones with data come from its saved variables behind `gmdbs[kind]` (`__gm2_base_storage` and `__gm2_storage_map`). Messages `GatherMate2NodeAdded` / `GatherMate2NodeDeleted` (zone, kind, coord, name) through `GatherMate2.RegisterMessage(listener, ...)`. All calls are in `pcall`.
- New nodes (`AddNode`, if `db.autoAdd`): into each route on that map with that kind and name, at `O.BestInsert`, unless a stop is already within 5 yards or a leg within `sight` yards; with `sight` the new stop goes at `O.Place` between its neighbours. Deleted nodes (`RemoveNode`) leave routes without sight, if within 1 yard (the others wait for Rebuild).

## Drawing

- World map: a data provider (`WorldMapFrame:AddDataProvider`) with one pin the size of the canvas (`DenormalizeHorizontalSize(1)`), frame level type `PIN_FRAME_LEVEL_MAP_HIGHLIGHT`, ignoring the global pin scale. `Pin:Draw` draws the shown routes of the map shown, and of its child zones on a parent map (`C_Map.GetMapRectOnMap`, lines half as wide). Widths are divided by the canvas zoom so they stay the same on screen; `OnCanvasScaleChanged` redraws.
- Minimap: a frame over `Minimap` with lines, redrawn at most every 0.03 s and only when your position, facing, the zoom (`C_Minimap.GetViewRadius`) or a setting changed. Your position is `C_Map.GetPlayerMapPosition(route.mapID, "player")` (nil off that map: nothing drawn). Pixels per yard = half the minimap's width / view radius. With `rotateMinimap` on, offsets (east, south) turn by `GetPlayerFacing()`: x' = x cos f − y sin f, y' = x sin f + y cos f. Segments are clipped to the circle (`ClipCircle`), or to the square if `GetMinimapShape()` says anything but ROUND (`ClipSquare`).
- Lines come from pools (`LinePool`): a white texture tinted with `SetVertexColor`, `SetThickness`.
- Color and opacity (since 1.5.0), each map on its own: `db.worldAlpha` / `db.minimapAlpha` (percent, 10-100; replaced the shared `db.alpha`, which `LoadSettings` copies into both once and then clears), `db.worldRouteColor` / `db.minimapRouteColor` (default true: each route's `color`), else `db.worldColor` / `db.minimapColor` `{r,g,b}` (default gold). `GP:LineColor(route, "world"|"minimap")` picks the color, `GP:SetLineColor(where, r, g, b)` sets the map's one color. `LoadSettings` copies table defaults fresh and puts a broken color back to the default, clamping each part to 0-1. The minimap's redraw key includes its opacity and color settings.
- Right-click on the minimap button (`ToggleLines`) turns both kinds of line off and remembers which were on (`db.hiddenWas`).

- 1.2.0 bug (fixed 1.2.1): `r.rebuild` (a plain `FlatButton`) never had `T.Disabler`, so `r.rebuild:SetDisabled` in the Routes refresher was a nil call as soon as a zone had a route. `GP:RefreshConfig` runs the refreshers in order, so the error stopped everything after it: New route's zone menu kept `keys = {}` (clicking it did nothing), its label and note stayed empty and the sliders never got their `Refresh`. Since 1.0.0; it only showed once a route existed. The test stub hid it because any unknown method on a fake frame was a no-op; now the methods the addon adds itself (`ADDON_METHODS` in `tests/wowstub.lua`: `SetDisabled`, `SetOn`, `IsOn`, `SetHover`, `Paint`, `Refresh`, `Choose`, `SetContent`) read nil unless added, as in the game. Add to that list when Theme.lua or Options.lua grows another such method.

## Tests

`lua5.1 tests/run.lua` (also run by GitHub Actions on every push and before every release). `tests/wowstub.lua` fakes the game: frames take any method (a field never set reads as a function, so tests use `rawget`), `Show` on a hidden frame runs its OnShow, lines remember their points, a world map that makes pins from the mixin, Elwynn Forest in Eastern Kingdoms, and `FakeGatherMate` with nodes and messages. `tests/run_tests.lua` checks the solver (the shortest loop on 8 nodes, a shuffled ring), making routes from the window, world map and minimap lines (positions, rotation, clipping), nodes found and deleted later, New route opening blank, editing a route (cancel, name clash, save, no nodes), renaming, hiding and deleting, saved data, and no GatherMate2.

**Not yet seen in game**: everything (first release). Worth checking first: lines on the world map (layer, width when zoomed), minimap lines lining up with GatherMate2's minimap icons (and turning with a rotating minimap), and `GetMapWorldSize` giving Forever's zone sizes. Also (1.1.0): the New route tab with both sliders fitting under the list, and how far Find Herbs/Minerals really shows nodes (to pick the best default for Pass within). Also (1.5.0): the Display tab's Lines card with the two color rows, and the color picker opened from its Line color squares. Also (1.2.1): Edit, Rebuild and Delete fitting beside the name box on a route row, the two info lines and Show under them; Cancel under Save changes on the New route tab.
